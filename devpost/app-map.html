Autofix

A rule-driven vulnerability remediation engine. You hand it a rule — a vulnerable pattern plus its known-good fix — and a Python repo; it finds every instance, asks an AI model for a context-aware fix at each site, verifies on a fresh branch with the test suite, and hands back a reviewable diff.

Kernel: pluggable rule data, not hardcoded logic — new vuln class = new YAML file

Matcher matcher.py · 174 loc

DETERMINISTIC

Compiles the DSL to a libcst visitor. A bare name matches md5() and hashlib.md5() alike; a dotted name (yaml.load) matches that path exactly, no over-match. Each Match carries its full start+end span — the key to precise splicing.

Transformer transformer.py · 548 loc

AI · SHORT LEASH

Per match: one call expression + read-only context → strands-agents structured output {replacement, confident, reason}. Splices via libcst only if confident and parseable, and adds any imports the fix needs. Runs matches with bounded concurrency, a per-match timeout, and retry+backoff; a failure becomes an isolated error, never a sunk run. Pluggable provider: Bedrock (default) or Ollama.

DETERMINISTIC

Lands fixes on autofix/<timestamp>, commits, runs pytest (--no-test skips it). Standalone repos branch in place; nested targets are copied + git init'd, so your tree is never touched. Names the likely culprit on red.

DETERMINISTIC

Decisions that shaped the code

libcst over stdlib ast

A concrete syntax tree preserves formatting, so a fix produces a one-line diff instead of a reformatted file. The heavier API is the price of the "just read the clean diff" promise.

The AI on a short leash — one snippet in, one structured object out

The model only judges this site; our code owns splicing, skipping, branching, and testing. That fence is what makes "AI edits your codebase" trustworthy — and it stayed intact through every hardening milestone.

Pluggable provider, default AWS Bedrock (Claude Sonnet 4.5), Ollama retained

The confident-vs-skip judgment was the real risk; two local models got it wrong in opposite directions. The identical structured_output path behind both backends made the swap nearly free.

Key replacements by full span; strip redundant trailing methods

A nested md5(...) and its outer .hexdigest() share a start position — start-only keying replaced the wrong node. Both edge cases are pinned by regression tests.

One failure never sinks the run

Transforms run concurrently, each with a timeout and retry; a hang or provider error becomes an isolated error result while every other fix proceeds. The fence's promise — bad output is skipped and recorded, never applied — now also covers failure modes.

Add-imports unlocks a class of fixes as pure rule data

A rule can declare ensure_import; a libcst codemod adds it iff missing when the fix applies — so random→secrets stays runnable, and the new power is still data, not engine logic.

Honest, approximate cost

The SDK's structured-output path surfaces no provider token counts, so usage is estimated from prompt/response text and clearly labeled approximate rather than dressed up as a billed figure.

A practice to reuse

Fence the AI, own the mechanics

Autofix's trust comes from a boundary you can redraw in any AI feature: let the model make the one judgment only it can, and keep everything verifiable in ordinary code around it.

  1. Name the single judgment. Here: "is this specific call a real fix or a false positive?" — not "rewrite my file."
  2. Demand structured output. A typed {result, confident, reason} (pydantic) turns free text into something your code can branch on.
  3. Validate before you act. Parse the model's output; on failure, skip and record — never corrupt state on bad output.
  4. Prove it deterministically. Wrap the edit in a branch + test run so the AI's proposal arrives with evidence, not just confidence.
