Autofix

A rule-driven vulnerability remediation engine. You hand it a rule — a vulnerable pattern plus its known-good fix — and a Python repo; it finds every instance, asks an AI model for a context-aware fix at each site, verifies on a fresh branch with the test suite, and hands back a reviewable diff.

Kernel: pluggable rule data, not hardcoded logic — new vuln class = new YAML file

Decisions that shaped the code

libcst over stdlib ast

A concrete syntax tree preserves formatting, so a fix produces a one-line diff instead of a reformatted file. The heavier API is the price of the "just read the clean diff" promise.

The AI on a short leash — one snippet in, one structured object out

The model only judges this site; our code owns splicing, skipping, branching, and testing. That fence is what makes "AI edits your codebase" trustworthy.

Pluggable provider, default AWS Bedrock (Claude Sonnet 4.5), Ollama retained

The confident-vs-skip judgment was the real risk; two local models got it wrong in opposite directions. The identical structured_output path behind both backends made the swap nearly free.

Key replacements by full span; strip redundant trailing methods

A nested md5(...) and its outer .hexdigest() share a start position — start-only keying replaced the wrong node. Both edge cases are pinned by regression tests.

Verify in an isolated copy for non-repo targets

Branching in place on a target nested inside another repo would corrupt the parent. Copy + git init keeps the demo safe and mirrors the clone-URL path.

A practice to reuse

Fence the AI, own the mechanics

Autofix's trust comes from a boundary you can redraw in any AI feature: let the model make the one judgment only it can, and keep everything verifiable in ordinary code around it.

  1. Name the single judgment. Here: "is this specific call a real fix or a false positive?" — not "rewrite my file."
  2. Demand structured output. A typed {result, confident, reason} (pydantic) turns free text into something your code can branch on.
  3. Validate before you act. Parse the model's output; on failure, skip and record — never corrupt state on bad output.
  4. Prove it deterministically. Wrap the edit in a branch + test run so the AI's proposal arrives with evidence, not just confidence.
